# Site design and SEO audit

## Inventory

The public build has a homepage, two published articles, Archive, About, and the existing 404 page. The password draft remains unpublished. The shared Jekyll shell uses `default`, `page`, and `post`; ClickFix has a dedicated case-study layout. The original main stylesheet came from the Hacker-Blog theme, while ClickFix had its own light stylesheet. The original site had no active JavaScript unless the optional analytics setting was enabled.

## Findings before this branch

- The main site used a dark terminal palette and monospace body copy; ClickFix switched to a light paper surface, serif copy, and unrelated orange/blue controls.
- Header and footer structures were separate. ClickFix had a useful section index, but some index links no longer matched the article's headings.
- The shared head wrote a `<title>` as well as `jekyll-seo-tag`, causing duplicate titles. The homepage and older post had generic or missing descriptions.
- About had no layout. Long KernelCon code and table content widened the page on a phone.
- The RSS self link pointed to `/feed.xml` although the feed lives at `/atom.xml`. The sitemap included the 404 and Google verification file.

## Standardized

- One dark palette, terminal brand, shared header/navigation/footer, focus treatment, type scale, reading width, link style, code treatment, tables, and image constraints. The homepage keeps its simple post list.
- Shared `head.html` uses one SEO tag output and one base stylesheet; ClickFix adds only its component stylesheet. Both published articles use the same sidebar and article card. The ClickFix browser title is shorter for search results while its visible article title remains unchanged.
- Page and post templates share the same shell. About now uses the page template. The sitemap omits utility pages, and the RSS self link matches its published path.
- Local Gemfile versions match the core Jekyll and configured plugin versions listed for GitHub Pages.

## Preserved differences

ClickFix keeps its curated section links, advisory warning, figures, details, video, and lab links. KernelCon keeps its original challenge images, terminal transcript, and DNA table; its sidebar links are generated from the existing headings. The same small local script supplies section links for future ordinary posts. The body of both published articles is byte-for-byte unchanged. The existing post URLs and generated heading IDs remain in place. No framework, analytics service, or external font was added.

## Validation

A Jekyll build completed with Jekyll 3.10.0 and the configured GitHub Pages plugin versions. Six rendered HTML pages were checked: one title, one description, one canonical URL per page; 124 link and asset references inspected with no missing local target or fragment; and 23 rendered images with no load failures in Chrome. Sitemap and feed XML parsed successfully. Desktop (1440 × 900) and phone (390 × 844) Chrome checks found no page-wide overflow on the homepage, both articles, Archive, About, or 404. Both article sidebars link to existing headings. The long code and table content scroll inside their own containers. Keyboard focus on the skip link has a visible outline.

The HTML validator reported no structural markup errors after excluding its rules for output formatting generated by Jekyll and its SEO plugin. It still reports five missing `scope` attributes on one legacy KernelCon Markdown table header. The table's source and data were left unchanged under the content-preservation requirement.
